# Практична робота: AWS CLI та Python SDK (boto3)

## Сценарій і підготовка

У навчальному AWS-акаунті можуть бути S3-бакет, IAM-користувачі та групи. Потрібно перевірити ресурси,
додати призначеного користувача до навчальної групи, дослідити її політику та
перевірити EC2 у вибраному регіоні. Виконайте той самий сценарій двічі: спочатку через AWS CLI,
потім через Python SDK для AWS — `boto3`.

Перед початком:

- Використовуйте лише навчальний акаунт і профіль AWS, надані викладачем. Перевірте активну
  ідентичність і регіон. Для EC2 використовуйте один і той самий регіон в обох частинах.
- Запишіть назви **призначеного** користувача та групи. У прикладі це `user-1` і `S3-Support`,
  але у вашому акаунті назви можуть бути іншими.
- Для зміни членства потрібен дозвіл `iam:AddUserToGroup`; для повернення початкового стану —
  `iam:RemoveUserFromGroup`. Якщо цих прав немає, виконайте частину читання та зафіксуйте помилку.
- Не створюйте ключі доступу, користувачів, групи, політики, бакети або EC2-інстанси для цієї роботи.

## Завдання 1. Той самий сценарій через AWS CLI

1. Перевірте активну ідентичність через `aws sts get-caller-identity`. Виведіть список бакетів
   командою `aws s3 ls` і запишіть назву одного з них. Якщо бакетів немає, зазначте це.
2. Отримайте списки через `aws iam list-users` і `aws iam list-groups`. Знайдіть призначеного
   користувача та групу.
3. Перевірте склад групи командою `aws iam get-group` **до зміни**. Якщо користувач уже входить
   до неї, не додавайте його вдруге. Якщо не входить і групу призначено для цієї роботи, додайте
   його командою
   `aws iam add-user-to-group`.
4. Повторно отримайте склад групи та переконайтеся, що користувач є в списку.
5. Виведіть прикріплені до групи керовані політики командою
   `aws iam list-attached-group-policies`. Знайдіть `AmazonS3ReadOnlyAccess`, якщо її прикріплено.
   Для її ARN отримайте метадані через `aws iam get-policy`, визначте `DefaultVersionId`,
   а потім прочитайте документ цієї версії через `aws iam get-policy-version`.
   Знайдіть у документі дозволені дії S3 та охоплені ресурси. Якщо такої політики немає,
   покажіть фактично прикріплені політики; нічого не прикріплюйте самостійно.
6. Виконайте `aws ec2 describe-instances` у вибраному регіоні. Визначте кількість знайдених
   інстансів та їхні стани або переконайтеся, що інстансів немає.
7. Якщо саме в цій частині ви додали користувача до групи, після фіксації результату видаліть
   **лише це** членство командою `aws iam remove-user-from-group` і перевірте початковий стан.

**Що здати:** один або кілька скріншотів термінала, на яких видно виконані команди та їхні
результати: списки ресурсів, склад групи до й після дії, політику та її версію, перевірку EC2
і відновлення початкового складу групи, якщо ви його змінювали. Не додавайте окремий звіт.

## Завдання 2. Аналогічний сценарій через Python SDK

Створіть скрипт `aws_inspect.py` з `boto3`. Скрипт має працювати з тим самим навчальним профілем,
користувачем, групою та регіоном, що й у завданні 1.

1. Створіть `boto3.Session` для навчального профілю та клієнти STS, S3, IAM і EC2.
   Перевірте ідентичність через `sts.get_caller_identity`, не виводячи повний Account ID.
2. Викличте `list_buckets`, `list_users` і `list_groups`. Виведіть назви бакетів, користувачів
   і груп. Для списків IAM врахуйте посторінкову видачу результатів.
3. Викличте `get_group` і покажіть учасників до зміни. Якщо призначеного користувача немає в
   групі та зміну дозволено, викличте `add_user_to_group`. Повторно прочитайте склад групи.
4. Через `list_attached_group_policies`, `get_policy` та `get_policy_version` знайдіть і
   дослідіть ту саму керовану політику, що й у завданні 1. Версію беріть із відповіді
   `get_policy`, а не записуйте її номер у коді.
5. Викличте `describe_instances` у тому самому регіоні. Виведіть кількість інстансів та їхні
   стани; якщо їх немає, виведіть зрозуміле повідомлення. Врахуйте посторінкову видачу.
6. Обробіть помилки браку дозволів так, щоб скрипт повідомляв, яка операція не вдалася.
   Не виводьте секретні ключі або токени.
7. Якщо скрипт додав користувача до групи, після фіксації результату викличте
   `remove_user_from_group` для повернення початкового стану. Якщо користувач уже був у групі,
   скрипт не повинен видаляти його.

**Що здати:** лише файл `aws_inspect.py` з кодом. Скрипт має виводити результати перевірок у
термінал під час запуску; окремий звіт або скріншоти для цієї частини не потрібні.
