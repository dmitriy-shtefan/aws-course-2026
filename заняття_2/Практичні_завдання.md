# Безпека та керування доступом (IAM)

## Частина 1

### Завдання 1. Створення IAM-користувачів

Мережа приватних клінік упорядковує доступ до свого AWS-акаунту. Замість спільного облікового запису
потрібно створити окремих IAM-користувачів для працівників.

Створіть таких користувачів:

- `ivan_admin`;
- `olha_registry`;
- `denys_support`.

Вимоги:

1. Відкрийте сервіс IAM в AWS Management Console.
2. Перейдіть до розділу **Users**.
3. Створіть трьох указаних IAM-користувачів.
4. Переконайтеся, що всі вони є у списку користувачів.

Для підтвердження результату підготуйте скріншоти:

- загального списку IAM Users із трьома створеними користувачами;
- сторінки користувача `ivan_admin`;
- сторінки користувача `olha_registry`;
- сторінки користувача `denys_support`.

### Завдання 2. Створення IAM-груп

Користувачів уже створено. Тепер об'єднайте працівників у групи відповідно до їхніх робочих функцій.

Використовуйте таких користувачів:

- `ivan_admin`;
- `olha_registry`;
- `denys_support`;
- `iryna_support`;
- `maksym_registry`.

Вимоги:

1. Відкрийте сервіс IAM і перейдіть до розділу **User groups**.
2. Створіть групи `registry_team` і `support_team`.
3. Додайте `olha_registry` та `maksym_registry` до групи `registry_team`.
4. Додайте `denys_support` та `iryna_support` до групи `support_team`.
5. Не додавайте `ivan_admin` до жодної групи.
6. Перевірте склад обох груп і відсутність груп у `ivan_admin`.

Для підтвердження результату підготуйте скріншоти:

- списку IAM User groups;
- складу групи `registry_team`;
- складу групи `support_team`;
- сторінки `ivan_admin`, де видно, що користувач не входить до жодної групи.

### Завдання 3. Призначення політик доступу

Користувачі та групи вже створені. Призначте їм різні права доступу відповідно до ролей.

Використовуйте:

- користувача `ivan_admin`;
- групу `registry_team`;
- групу `support_team`.

Вимоги:

1. У розділі **Users** відкрийте користувача `ivan_admin`.
2. Призначте йому політику `AdministratorAccess`.
3. У розділі **User groups** відкрийте групу `registry_team`.
4. Призначте цій групі політику `IAMUserChangePassword`.
5. Відкрийте групу `support_team` і призначте їй політику `ReadOnlyAccess`.
6. Перевірте, що кожній сутності призначено правильну політику.

Для підтвердження результату підготуйте скріншоти:

- сторінки `ivan_admin` із політикою `AdministratorAccess`;
- сторінки `registry_team` із політикою `IAMUserChangePassword`;
- сторінки `support_team` із політикою `ReadOnlyAccess`.

## Частина 2

### Завдання 4. Застосування принципу Least Privilege

Під час перевірки безпеки з'ясувалося, що окремі працівники можуть мати надмірні права. Скоригуйте
налаштування відповідно до принципу найменших привілеїв.

Використовуйте:

- користувача `ivan_admin`;
- групу `registry_team`;
- групу `support_team`.

Вимоги:

1. В IAM відкрийте групу `support_team`.
2. Видаліть надмірно широку політику, якщо її призначено.
3. Залиште для `support_team` лише політику `ReadOnlyAccess`.
4. Відкрийте `registry_team` і видаліть надмірно широку політику, якщо вона є.
5. Залиште для `registry_team` лише політику `IAMUserChangePassword`.
6. Переконайтеся, що `ivan_admin` має політику `AdministratorAccess`.

Для підтвердження результату підготуйте скріншоти:

- сторінки `support_team`, де залишилася лише політика `ReadOnlyAccess`;
- сторінки `registry_team`, де залишилася лише політика `IAMUserChangePassword`;
- сторінки `ivan_admin` із політикою `AdministratorAccess`.

### Завдання 5. Налаштування MFA та перевірка подій у CloudTrail

Завершіть базове налаштування доступу: посильте захист облікового запису адміністратора та перевірте
відстеження дій користувачів за допомогою AWS CloudTrail.

Використовуйте:

- користувача `ivan_admin`;
- сервіс AWS CloudTrail.

Вимоги:

1. В IAM відкрийте користувача `ivan_admin`.
2. Налаштуйте для нього багатофакторну автентифікацію MFA.
3. Переконайтеся, що MFA увімкнено.
4. Відкрийте сервіс CloudTrail і перейдіть до розділу **Event history**.
5. Перегляньте список подій і знайдіть дії, пов'язані з IAM.
6. Відкрийте одну з подій і перегляньте її подробиці.
7. Знайдіть назву й час події, виконавця дії та використаний AWS-сервіс.

Для підтвердження результату підготуйте скріншоти:

- сторінки `ivan_admin`, де видно, що MFA увімкнено;
- розділу CloudTrail Event history зі списком подій;
- подробиць однієї події CloudTrail.
